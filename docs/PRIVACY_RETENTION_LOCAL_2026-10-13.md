# 隐私授权与对话留存：前端交付与发布验证

2026-10-13。本次隐私功能已在最新远端基线中完成合入与本地验证，通过本仓库 GitHub Actions 发布 Azure。具体发布提交、Actions 结果及 revision 以关联 PR 的发布记录为准。

聊天输入框下新增敏感信息提示、服务器确认的保存期限、到期时间和「隐私与保存」入口。用户可直接聊天，不需要先完成授权表单。首次打开设置会先创建一段空会话，以便在发送第一条消息之前修改该会话的策略。

## 已实现

- 逐轮保存：新会话沿用服务器默认值，目前为 30 天；按每轮成功回答分别起算。
- 整段会话保留：切换时预填 14 天，可以在服务器允许的范围内修改，当前为 1–90 天；从最后一轮成功回答起算。
- 不保存新的历史：提示临时上下文闲置 24 小时清除、服务重启可能丢失。已有历史的删除单独勾选确认；未勾选则按原期限保留。
- 期限修改：增加天数默认不自动延长已有记录；已有历史展期、保存当前临时内容、删除已有历史均使用独立选项。修改后从服务器读取策略，并刷新已保存的聊天历史。
- 省市地区、昵称、回答偏好分别授权、撤回与展期，各项初始不勾选。个人信息授权仅供登录用户使用；访客可修改会话留存并继续聊天。
- 地区主动选择省级地区、可选城市代码、事件发生地或求助地。仅展示后端批准的地区选项，不调用浏览器定位或使用 IP 推断。后端目前只提供城市代码，没有城市名称；前端明确标注行政区划代码，城市名称需要扩展该接口契约。
- 已授权原值不会从后端回填到表单。更新需要重新输入内容，展期沿用服务器上的内容；表单值不写入 localStorage/sessionStorage。
- 隐私状态加载失败时，不影响聊天发送；未确认策略不会显示伪造的保存天数。
- 409 提示刷新版本后重新选择；202 提示恢复保护记录仍在同步。查询本地设置不能证明独立 ledger 已同步，因此刷新不会自动把处理中改成完成。若本地历史已经删除，立即刷新聊天内容，避免继续展示旧记录。
- 网关允许 GET 隐私选项与状态，以及 PATCH 会话政策和三个批准字段；保留 Origin 校验、身份转发与后端状态码。原聊天删除请求收到 202 时，也不会误报完成。
- 输入区使用 ResizeObserver 回报高度，为历史内容留出相应空间。
