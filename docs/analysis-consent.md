# 游客注册邀请与团队分析授权

游客完成第六轮成功回复后，或点击聊天页右上角头像菜单的「注册 / 登录」，会打开同一个弹窗。
中断或失败回复不计入轮数。
关闭后不再自动提醒，头像菜单仍可重新打开。
危机提示出现时优先显示危机提示。

弹窗标题为「注册账号，继续和小安聊聊」。复选框默认不勾选，文案为：

> 我同意将本次游客对话及登录后的对话经过去标识化处理后保存，供团队分析，用于改进小安的回复与服务。

辅助说明为「此项为自愿选择，不勾选也可注册或登录。
」两个按钮分别为「注册 / 登录」「暂时不用」。
点击前者保存明确的 true/false 选择，成功后进入 `/sign-up` 的 Clerk 注册/登录流程；后者直接回到聊天。
快速离开仍保留。

## 授权记录

- `POST /v1/analysis-consent` 的 `prepare` 操作只允许未登录用户，验证同源、固定文案版本及布尔值。当前游客会话须匹配 HttpOnly `xiaoan_guest` 凭证的 SHA-256、未关联账号、未过期；不接受客户端指定用户身份。
- 服务端生成随机凭证，数据库只保存摘要，浏览器通过 HttpOnly、SameSite=Lax、Path=/v1 的一小时 cookie 携带。暂存选择本身不会开放 Feedback。
- Clerk 返回聊天页后，`complete` 操作使用经验证的当前账号，以事务绑定暂存选择。相同账号的重试幂等，不允许另一个账号使用已消费凭证；旧的暂存选择不能覆盖较新的决定。成功后清除 cookie，快速离开也显式清除该 cookie。
- 仅当前游客会话被显式纳入。账号范围覆盖选择时间之后新建的会话，其他历史会话不追溯开放。不会调用「关联本设备所有游客记录」接口，也不会改变已有保存期限。
- 未勾选保存为 false；没有记录、暂存未完成或过期不会新增授权。完成保存失败时提供重试，聊天仍可用。

## Feedback

用户分组、会话列表、详情与导出共用服务端授权条件。
独立的失败请求列表同样按授权筛选，仅显示错误阶段、状态和代码，未去标识化的输入及错误说明不返回。
一般记录必须有有效的明确授权，同时保留账号状态与游客有效期条件。
独立的内部测试清单 `xiaoan_prelaunch_feedback` 仅允许查看 2026-11-25 01:12:36 (Asia/Hong_Kong) 上线前的会话；此范围由一次性内部数据回填明确标记，不改变任何用户的个人授权，也不匹配上线后的会话。
回填后的旧游客记录仅通过管理员 Feedback 后台访问；其游客 `expires_at` 置为 NULL，以防旧会话凭证重新访问并防止过期清理任务删除这些内部测试记录。

此分析视图读取已有 `user` / `assistant` 去标识化字段，不回退到 `user_original` / `assistant_original`。
完整 Debug、推理文本和 IP/地理位置未经统一去标识化验证，因此这次分析视图不返回这些字段，仅保留开始/完成时间等指标；用户自己的聊天记录和原有诊断存储不变。
已有评分和主动提交的改进建议保留。

本变更控制团队分析访问；对话去标识化仍依赖已有后端处理链路，并未新增对底层存储的清洗或延长留存任务。

## 部署和验证

`db/migrations/005_analysis_consent.sql` 已在生产应用前显式执行；请求处理器不会自动建表。
历史测试会话通过 `db/operations/restore_prelaunch_test_feedback.sql` 一次性回填，不重建已删除的记录。
过期暂存记录可由数据库运维定期清理，应用不会消费过期记录。

定向检查：

```sh
node --test tests/guest-login.test.cjs tests/analysis-consent.test.cjs tests/access.test.cjs tests/guest-login-dialog.test.cjs
node_modules/.bin/tsc --project tsconfig.chatflow.json --noEmit
```

测试使用模拟认证/数据库；上线时另在真实 PostgreSQL 中验证迁移、访问筛选条件及运行角色权限。

回填以固定会话清单和最大轮次为边界，不修改个人授权；再次执行不会扩充清单。
上线后的游客会话及历史会话中后来新增的轮次仍必须经独立授权才会进入 Feedback。

回填同时保存原有游客及轮次到期时间；仅固定清单中的旧测试轮次延长至 9999 年，作为内部测试长期留存（使用有限时间戳兼容现有 JSON 接口）。
后续轮次的保存期限、个人删除操作和游客授权规则保持原样。

## 撤回分析授权

登录后可在「隐私与保存」里撤回。撤回会即时收回账号和已关联游客对话在分析后台的授权。用户仍可按原保存设置使用对话，已导出的分析结果与已提交的评分和建议继续保留。内部测试清单按其独立规则管理。重新授权只覆盖新授权之后创建的账号对话。

发布应用前，请在同一 PostgreSQL 上先执行 `db/migrations/008_analysis_consent_events.sql`。
