## 要達成的結果

使用者在不依賴視覺、滑鼠或持續按住手勢的情況下，能獨立完成：進入聊天 → 輸入或錄音 → 核對文字 → 發送 → 知道回覆狀態 → 閱讀回答 → 追問 → 切換歷史 → 評分。

沿用目前視覺風格。核心操作直接具備無障礙能力，不另設需要先找到的「無障礙模式」，不偵測使用者是否開啟讀屏。

本次依據：前一輪正式站無障礙樹檢查與本次本地原始碼複查。各讀屏軟件尚未真機驗收；本地工作樹包含既有未提交變更，實作時須保留。

採 WCAG 2.2 A＋AA 為基本驗收目標；44×44 CSS px 操作範圍、較大起始字體及點按錄音為額外的包容性目標。沿用暖白、棕色與淡紫風格，不增加進入聊天前的問卷或設定流程。

前輪正式聊天頁觀察到快速退出為白字／#D9B18D，對比約 1.98:1。候選新配色的靜態對比已核算：退出 #713B20／#FFEBCF 約 7.68:1，主要操作白字／#795035 約 6.97:1，次要文字 #655649／#FBF9F6 約 6.70:1；最終仍須檢查實際背景、各狀態及所有頁面。

## 1. 閱讀與操作順序

頁面提供「跳到對話內容」「跳到輸入框」入口，鍵盤聚焦時可見。主區用 main；歷史對話 nav 與資源區有清楚名稱。

- 對話內容：按時間順序，明確標示「你」「小安」；每則訊息用可定位的文章及標題，避免只靠頭像區分發話者。
- 每則小安回答：正文 → 相關建議 → 評分／其他操作。
- 輸入區：有可見標籤「和小安說說話」；輔助說明包含 Enter 發送、Shift+Enter 換行；輸入法組字期間 Enter 不送出。
- 回答生成時允許起草下一則訊息；發送暫不可用，停止回覆按鈕保留在同一位置。
- 回答完成後提供「閱讀最新回答」入口，將焦點移到最新回答的標題／容器，再由讀屏正常閱讀正文。
- 所有動作使用原生 button／a／input；自訂共用 Button 保留既有樣式 API，但渲染原生 button，校對所有呼叫端事件型別及表單 type。
- 歷史對話的切換與刪除為同一列中的兩個獨立按鈕，禁止巢狀按鈕；目前對話用 aria-current="true"。
- 重複的刪除／評分按鈕名稱帶對話或回覆序號，避免按鈕列表出現一排無法區分的「刪除」。

## 2. 回覆通知：知道狀態，保留閱讀控制

預設「只通知狀態」，不自動把整段敏感回答送進讀屏朗讀佇列。設定提供「回覆完成後自動朗讀全文」，預設關閉；說明此選項會透過使用者的讀屏播報。不新增網站 TTS，不搶佔讀屏。

這項設定只保存在當前分頁記憶體；重新載入恢復預設，切換對話後不補播舊訊息。讀屏本身仍可能按其設定朗讀聚焦內容或頁面變動，本設計控制的是網站主動通知。

| 事件 | 通知文字（產品使用簡體中文） | 焦點 |
| --- | --- | --- |
| 成功開始送出本輪請求 | 消息已发送，小安正在回复。 | 留在輸入框或當前操作位置 |
| 第一段回答出現 | 不額外重複播報 | 不移動 |
| 本輪成功完成 | 小安已回复。可选择“阅读最新回答”。 | 不移動 |
| 使用者停止 | 已停止回复，已生成的内容仍可阅读。 | 按現有停止行為回到輸入框 |
| 失敗 | 本輪錯誤原因及可行動作，例如「回复中断，可阅读已生成内容，或重试。」 | 不搶焦點 |
| 切換對話完成 | 已切换到〔对话名称〕。 | 見焦點表 |
| 使用者主動啟用全文通知且本輪成功完成 | 該輪最終回答，只播報一次 | 不移動 |

技術策略：

1. 可見聊天內容保留正常文件閱讀，使用有名稱的 region；預設不掛會自動播全文的 live log。
2. 頁面預先掛載獨立 status（polite、atomic）處理簡短狀態；不在每個串流 token 更新時改寫通知區。
3. 需要立即處理的錯誤使用一個 alert；保留既有 failure alert 並避免 Toast／status 再播同一錯誤。一般成功提示用 status。
4. 開啟全文通知時，使用獨立 polite 通知區，只在成功完成後填入該輪最終文字；不與狀態區重複播正文。長文通知仍須真機檢查截斷／打斷行為；「閱讀最新回答」始終保留。
5. 以「對話 ID＋本輪操作 ID」識別通知。歷史載入、React 重渲染、換成服務端 response_id、開關設定均不補播；重試屬新操作，完成通知可再出現。
6. 停止和失敗不誤報「完成」；必須使用 hook 的明確終止原因，不能只觀察 isResponding 從 true 變 false。停止後遲到的串流事件不得觸發新通知。
7. 不把整個頁面標成 busy；如用 aria-busy，僅作用在正在更新的回答區，不能封住狀態通知和停止按鈕。

取捨：W3C 提供 role=log 的聊天記錄模式。本案預設採文件區＋獨立狀態通知，讓使用者控制敏感全文何時被主動播報。

## 3. 錄音：兩種方式，均須手動發送

輸入框旁提供具名的「錄音操作方式」選擇：點按錄音（新預設）、按住說話（可切換）。這是所有使用者可用的選項，放在錄音控制旁，不藏在讀屏專屬設定。只保存於當前分頁記憶體。

| 狀態 | 點按方式的主按鈕 | 其他操作與通知 |
| --- | --- | --- |
| 閒置 | 开始录音 | 可切換操作方式 |
| 首次請求權限 | 等待麦克风授权（不可重複啟動） | 取消；授權完成只準備裝置，提示「麦克风已就绪，请选择开始录音。」 |
| 錄音中 | 结束录音并转写 | 取消录音；宣告已開始；秒數可見但不逐秒播報 |
| 接近時限 | 同上 | 如採提醒，只在剩 10 秒時通知一次；沿用 55 秒上限 |
| 轉寫中 | 正在转写（不可重複啟動） | 取消转写；一次 polite 通知 |
| 轉寫成功 | 开始录音 | 「转写已加入输入框，请核对并修改，再点击发送。」 |
| 權限拒絕／轉寫失敗 | 重试录音（依錯誤類型） | 具體設定指引或文字輸入替代；不清除原草稿 |

點按方式用原生 click 同時覆蓋鍵盤 Enter／Space、讀屏雙擊和滑鼠。不得同時以 pointerdown 與 click 切換狀態，避免一次操作啟停兩次。錄音按鈕使用動態動作名稱，不使用 aria-pressed，以免在部分平台呈現成勾選控制。

按住方式繼續支援 pointer／鍵盤按住；兩種方式共用單一錄音工作階段。錄音、權限請求、轉寫期間鎖定方式選擇。點按方式切換焦點不取消錄音；使用者應能聚焦「取消录音」。切換對話、離開頁面、分頁進入背景、快速離開會取消並釋放麥克風。

取消轉寫後，遲到結果不能回填草稿。授權完成、結束錄音、轉寫成功、修改草稿都不呼叫發送。沿用目前錄音保存政策與提示，本方案不改保存期限或後端資料政策。

轉寫成功僅在焦點仍位於本次錄音控制／輸入區時回到輸入框；如果使用者已前往其他區域，保留其焦點並通知可回輸入框核對。

## 4. 快速離開、焦點與閱讀位置

快速離開採常駐文字「快速离开」，在標頭預留位置，不遮住設定、登入或內文。每個模態彈窗內另提供退出按鈕，確保背景 inert 時仍可操作。退出一步觸發，不加確認或倒數；沿用既有退出與清理範圍，不改後端保存政策。

本輪採固定標頭右側的位置，不提供拖曳調整；使用響應式標頭預留退出空間。可聚焦的說明入口交代 Esc 行為及「快速离开会隐藏当前页面并执行退出流程；不会清除浏览器历史。」服務端資料保存依現有隱私設定說明。


| 動作 | 焦點結果 |
| --- | --- |
| 頂部新建對話 | 到新對話輸入框；宣告已建立新對話 |
| 切換歷史對話 | 載入完成後到對話標題，再可跳輸入框；若載入失敗，留在切換控制並通知 |
| 展開／收起側欄 | 留在原切換按鈕，正確更新 aria-expanded／aria-controls |
| 手機打開歷史或資源覆蓋層 | 進入有名稱的 modal dialog，背景 inert；關閉後回觸發按鈕 |
| 桌面打開非模態資源面板 | 不鎖焦點；保留返回聊天的入口 |
| 開啟評分／確認刪除 | 聚焦標題或適當首個控制，焦點限制在彈窗；刪除預設聚焦取消 |
| 關閉彈窗 | 回到原觸發按鈕；觸發者已刪除時到下一列、上一列或新對話入口 |
| 資源隨回答更新 | 不搶焦點，不反覆播整個資源區 |

Esc 優先關閉最上層彈窗／選單／覆蓋層。關閉操作必須阻止事件繼續觸發全域快速離開。全域處理器檢查 defaultPrevented、組字狀態和目前覆蓋層；原生 dialog 的 cancel 路徑也需驗證事件次序。

無覆蓋層且非輸入法組字時保留原 Esc 快速離開行為，錄音或轉寫中亦相同，退出時取消工作並釋放麥克風。取消錄音／轉寫由獨立具名按鈕執行，不佔用 Esc。快捷鍵說明：「Esc 可关闭当前窗口；没有窗口打开时可快速离开。」禁止按鍵長按重複觸發。

儲存中的彈窗若暫時不能關閉，Esc 仍須被消耗，通知「正在保存，请稍候」，保留焦點及快速離開按鈕。危機選擇彈窗的關閉視為「暫不選擇」，不得記成使用者已安全；回到聊天並保留安全包入口。此互動已由使用者確認：繼續按鈕採「继续聊天」，移除要求使用者聲明已安全的文案。關閉後回到聊天的合理焦點位置，保留可鍵盤抵達的「查看安全包」入口；阻止此次 Esc 穿透至全域退出。

串流更新不強制捲動正在閱讀歷史的使用者；只有原本貼近底部時跟隨，離開底部則提供「有新回复，阅读最新回答」。焦點與視覺捲動分開處理。初始跟隨門檻為距底部 80 CSS px，待實機調整；使用者向上捲動或焦點留在舊訊息時停止跟隨。最新回答完成後，統一使用「阅读最新回答」入口；有更新且離開底部時使用「有新回复，阅读最新回答」。啟動入口才移焦並恢復跟隨；減少動態偏好下即時定位。

## 5. 實作分批

A、B 優先交付核心聊天操作；C 完成後才可宣告不依賴持續按住的完整語音任務可用。D 驗收覆蓋前三批。後續擴展首頁、文檔工具及資源頁：補充可文字聯絡渠道、服務時間與適用地區，讓無法安全說話或有聽語障礙的人也能求助；渠道須核實後呈現。


| 批次 | 工作與主要檔案 | 完成條件 |
| --- | --- | --- |
| A：基本操作 | base/button、sidebar、chat/answer、chat/question、quick-exit、各彈窗、聊天樣式 | 核心操作可 Tab 到達及 Enter／Space 啟動；Esc 關層不離站；退出按鈕對比及觸控範圍達標 |
| B：聊天通知 | hooks/use-chatflow、components/index、chat/index、answer、base/toast | 正確區分成功／停止／失敗；不逐 token 播、不播舊記錄；最新回答可定位 |
| C：點按錄音 | hooks/use-speech-input、chat/index | 兩種模式共用狀態機；所有錄音結果先入草稿；取消／遲到事件處理正確 |
| D：整體驗收 | layout、資源／隱私／登入／評分及真機 | 完整任務可獨立完成，焦點及內容不被浮層遮擋 |

優先處理聊天路徑的共用 Button；修改共用元件前列出所有使用處，避免表單誤提交、巢狀按鈕及事件型別回歸。實作前依專案要求查 Context7；視覺改版須先取得專案指定 ui-ux-pro-max 技能（本次未找到）。

## 6. 驗收矩陣與通過標準

首輪：Android 天坦＋Chrome、Android 保益悅聽＋Chrome、Windows 爭渡＋Chrome／Edge、iPhone VoiceOver＋Safari。基準補測：NVDA＋Chrome／Firefox、TalkBack＋Chrome。若使用者實際從微信進入，再加對應 Android／iOS 微信內瀏覽器；永德／陽光依目標使用者實際版本擴充。

每次記錄裝置、OS、讀屏版本、瀏覽器版本、步驟、實際朗讀文字、預期、結果與缺陷。這是測試覆蓋優先序，不是市場佔有率排序。

必測情境：

1. 無滑鼠完成新建、輸入、發送、停止、追問、切換歷史、評分。確認建議問題也可操作。
2. 串流長回答：開始通知一次、成功完成一次；不中途重讀全文；定位最新回答後能讀標題、列表、連結與正文。
3. 停止、超時、斷網、重試：正確播終止原因，不出現假的完成；原草稿／已生成內容可找回。
4. 歷史載入、切換、重新渲染不主動播舊全文；開啟全文選項也不追播。
5. 讀屏雙擊完成「開始→結束→轉寫→核對→手動發送」；移焦到取消可取消；按住模式仍可用。
6. 首次權限允許／拒絕、取消、錄音超時、背景切換、轉寫遲到：不偷啟動、不誤發送、不回填錯對話。
7. 每種彈窗／選單的 Esc、焦點限制與返回；無覆蓋層時快速離開正常。
8. 讀歷史時新內容不拖走位置；200% 縮放和手機軟鍵盤下，焦點控制仍可見。
9. 預設不主動播敏感全文；開啟全文選項後成功回答只通知一次，關閉後下輪恢復只播狀態。

程式驗證可使用針對性元件／狀態測試與靜態檢查；自動掃描只補充語義缺陷。真機朗讀與手勢結果單獨記錄，尚未測試的格子標「待驗證」。完整 build、端到端測試、安裝套件及 git push 依專案規則另行取得授權。

### 視覺、手機與認知負擔驗收

- 200% 文字、400% 縮放、320 CSS px 寬度及橫向畫面下，核心內容與操作不丟失，不以橫向捲動閱讀一般文字。
- 行高 1.5 倍、段距 2 倍、字距 .12em、詞距 .16em 時不截斷內容。
- iOS Safari／Android Chrome 軟鍵盤開啟後，輸入、發送、停止和退出可達，焦點不被固定區完全遮住。
- 驗證焦點外框不被裁切、一般文字對比至少 4.5:1、必要非文字控制資訊至少 3:1；44px 尺寸為本案操作目標。
- 將輸入框下說明分為操作、語音保存、隱私與 AI 限制；首次錄音前能讀到保存摘要及完整說明，不能因折疊而遺漏。
- 載入、捲動及過場支援減少動態偏好，並有文字替代；錯誤持續顯示，網絡恢復不自動重送。
